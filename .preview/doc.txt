1. 项目概述

      本项目实现了一个带图形用户界面的系统监控程序，用于实时观测操作系统的
运行状态。程序以 psutil 作为底层数据源，以 tkinter / ttk 构建桌面界面，界面按
Windows 任务管理器的组织方式设计：顶部“进程 / 性能”标签、左侧组件列表、
右侧大图表与统计列、底部概览状态栏。

      监控能力包括：
1. CPU 总体使用率与每个逻辑核心的使用率；
2. 物理内存、交换分区使用率；
3. 网络接收 / 发送速率与累计流量，网卡连接状态；
4. 磁盘 IO 读取 / 写入速率；
5. 各磁盘分区的容量使用率；
6. 进程列表：名称、状态、CPU 占比、内存占用、PID。

3.1 为什么自绘图表

• tkinter 属于 Python 标准库，安装成本低，符合“只需 pip install psutil 即可运
     行”的目标；

• matplotlib 嵌入 tkinter 会增加数十 MB 依赖，并带来字体、DPI 兼容问题；
• 需求是固定时间窗口的滚动曲线，Canvas 自绘约 200 行即可实现，启动更快，

     外观也能对齐任务管理器的细网格与淡色填充。

4.3 关键实现

4.3.1 速率计算
      网络与磁盘 IO 使用累计字节计数器，速率按两次采样的差值计算：

 rate = (counter_now - counter_last) / (t_now - t_last)

• 使用 psutil.net_io_counters(nowrap=True)、disk_io_counters(nowrap=True)，计数器
     溢出时自动修正；

• 差值小于 0 时按 0 处理；
• 采集线程启动时建立基线，暂停期间持续重置基线，恢复后不会出现速率尖峰；
• 启动前调用一次 cpu_percent(interval=None) 预热，避免第一帧恒为 0。

4.3.2 进程采样线程（性能取舍）
      在 Windows 上实测

psutil.process_iter(["pid","name","status","cpu_percent","memory_info"]) 遍历约 240 个进
程需 1.7 秒（其中名称约 0.66 秒、状态约 0.5 秒）。如果把这段逻辑放进 1 秒级
的主采样线程，会导致采样间隔被拉长、曲线出现断档。

      处理方式：
• 进程扫描放到独立守护线程 ProcessSampler，每 3 秒一次，与主采样节奏互不影

     响；

                              第 12 页
                         yxb 的任务管理器 · 系统说明文档

• 扫描时只请求 pid、cpu_percent、memory_info 三个属性；
• 进程名按 PID 缓存（同一 PID 的名称不会变化），退出进程的缓存会被清理；
• 只对排序后将要展示的前 80 个进程调用 Process.status()；
• 结果放在 threading.Lock 保护的缓存里，主采样线程读取后写入 Snapshot。

      实测优化后单次扫描约 1.0 秒，且发生在独立线程，主采样仍保持 1 秒间隔。
      进程 CPU 数值按逻辑核心数归一化（cpu_percent / cpu_count），与任务管理
器“占全部 CPU 的百分比”一致；否则多核进程会显示 300%、1300% 之类的
值。

5. 实现的主要功能

1. CPU 监控：总体占用率、每个逻辑核心占用率、主频、物理 / 逻辑核心数、系
     统负载、运行时长、60 点历史曲线。

2. 内存监控：物理内存占用率与已用 / 可用 / 总容量、交换分区使用率与容量、内
     存组成条、历史曲线。

3. 网络监控：接收 / 发送实时速率（B/s ~ GB/s 自动换算单位）、双曲线、累计流
     量、网卡连接状态与链路速率。

4. 磁盘 IO 监控：读取 / 写入实时速率、双曲线、分区数量与总容量。
5. 磁盘分区监控：盘符、文件系统、使用率条、已用 / 总容量。
6. 进程监控：名称、中文状态、CPU 占比、内存占用、PID，表头排序与名称筛选。
7. 交互控制：采样间隔 0.5/1/2/5 秒切换；暂停 / 继续采集；窗口缩放；关闭时安

     全停止后台线程。
8. 概览状态栏：进程数、CPU、内存、磁盘速率、网络速率、采集状态、采样次数、

     运行时长、psutil / Python 版本。

7.3 已知限制

• 网络速率统计的是所有网卡的合计值，未按适配器拆分；
• 磁盘 IO 为物理磁盘合计值，无法按分区区分（受 psutil 接口限制）；
• 进程列表按 CPU 降序只展示前 80 个进程，进程总数单独统计；
• 进程状态为采样瞬间的快照，且只对展示的 80 个进程读取；
• Windows 的系统负载为 psutil 模拟值，精度低于 Linux；
• 历史曲线固定保留最近 60 个采样点，切换间隔后曲线覆盖的时间跨度会变化；
• 进程页只做监控展示，不提供结束进程操作，以免误杀系统进程；
• 程序未打包为 exe，运行需本机安装 Python 与 psutil。

      速率计算：

 def _rate(current, previous, elapsed):
        if current is None or previous is None or elapsed <= 0:
               return 0.0
        delta = current - previous
        if delta <= 0:
               return 0.0
        return delta / elapsed
