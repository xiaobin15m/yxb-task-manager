## 1. 项目概述

本项目实现了一个带图形用户界面的系统监控程序，用于实时观测操作系统的运行状态。程序以 `psutil` 作为底层数据源，以 `tkinter` / `ttk` 构建桌面界面，界面按 Windows 任务管理器的组织方式设计：顶部“进程 / 性能”标签、左侧组件列表、右侧大图表与统计列、底部概览状态栏。

监控能力包括：

1. CPU 总体使用率与每个逻辑核心的使用率；
2. 物理内存、交换分区使用率；
3. 网络接收 / 发送速率与累计流量，网卡连接状态；
4. 磁盘 IO 读取 / 写入速率；
5. 各磁盘分区的容量使用率；
6. 进程列表：名称、状态、CPU 占比、内存占用、PID。

### 3.1 为什么自绘图表

- tkinter 属于 Python 标准库，安装成本低，符合“只需 `pip install psutil` 即可运行”的目标；
- matplotlib 嵌入 tkinter 会增加数十 MB 依赖，并带来字体、DPI 兼容问题；
- 需求是固定时间窗口的滚动曲线，`Canvas` 自绘约 200 行即可实现，启动更快，外观也能对齐任务管理器的细网格与淡色填充。

### 3.2 界面样式来源

没有使用第三方主题库，而是：

- `ttk.Style().theme_use("clam")` + 自定义 `TM.Treeview` / `TM.Treeview.Heading` / `TM.Vertical.TScrollbar` / `TM.TCombobox` 样式，去掉立体边框、改为白底扁平表头；
- 自定义浅色配色：窗口底色 `#f3f3f3`、内容白底、分隔线 `#e2e2e2`、强调蓝 `#0067c0`、图表蓝 `#0078d4` 与橙 `#c2690a`；
- 顶部标签用 `Label` + 2 px 下划线实现，选中项蓝色下划线 + 加粗，与任务管理器的标签栏一致。

## 4. 系统设计

### 4.1 总体架构

```
┌─────────────────────────────── 主进程 ─────────────────────────────────┐
│                                                                       │
│  ┌────────────────────────┐   queue.Queue(maxsize=2)   ┌────────────┐  │
│  │ SystemCollector        │ ────── Snapshot ──────────▶ │ UI 主线程   │  │
│  │ （主采样线程，1 秒）      │                          │ MonitorApp │  │
│  │ · cpu_percent          │ ◀── pause / resume / ───  │ · 轮询队列  │  │
│  │ · virtual_memory       │      set_interval        │ · 刷新两个页 │  │
│  │ · net_io_counters      │                          │ · 状态栏    │  │
│  │ · disk_io_counters     │                          └────────────┘  │
│  │ · disk_partitions      │                                          │
│  │ · net_if_stats/addrs   │      ┌──────────────────┐                │
│  │ · boot_time            │ ◀─── │ ProcessSampler   │ 进程列表缓存    │
│  └────────────────────────┘      │ （进程线程，3 秒） │ (加锁读写)     │
│                                  └──────────────────┘                │
└───────────────────────────────────────────────────────────────────────┘
```

- **主采样线程**：每 `interval` 秒采集 CPU / 内存 / 网络 / 磁盘 / 分区 / 网卡，结果写入容量为 2 的队列，队列满时丢弃旧数据；
- **进程采样线程**：每 3 秒遍历一次进程，结果保存在线程内的加锁缓存中，主采样线程生成快照时直接读取缓存；
- **界面主线程**：每 250 ms 轮询队列，只做界面更新，不执行任何阻塞式 psutil 调用；
- 磁盘分区、网络适配器变化缓慢，默认 10 秒刷新一次。

### 4.3 关键实现

#### 4.3.1 速率计算

网络与磁盘 IO 使用累计字节计数器，速率按两次采样的差值计算：

```
rate = (counter_now - counter_last) / (t_now - t_last)
```

- 使用 `psutil.net_io_counters(nowrap=True)`、`disk_io_counters(nowrap=True)`，计数器溢出时自动修正；
- 差值小于 0 时按 0 处理；
- 采集线程启动时建立基线，暂停期间持续重置基线，恢复后不会出现速率尖峰；
- 启动前调用一次 `cpu_percent(interval=None)` 预热，避免第一帧恒为 0。

#### 4.3.2 进程采样线程（性能取舍）

在 Windows 上实测 `psutil.process_iter(["pid","name","status","cpu_percent","memory_info"])` 遍历约 240 个进程需 **1.7 秒**（其中名称约 0.66 秒、状态约 0.5 秒）。如果把这段逻辑放进 1 秒级的主采样线程，会导致采样间隔被拉长、曲线出现断档。

处理方式：

- 进程扫描放到独立守护线程 `ProcessSampler`，每 3 秒一次，与主采样节奏互不影响；
- 扫描时只请求 `pid`、`cpu_percent`、`memory_info` 三个属性；
- 进程名按 PID 缓存（同一 PID 的名称不会变化），退出进程的缓存会被清理；
- 只对排序后将要展示的前 80 个进程调用 `Process.status()`；
- 结果放在 `threading.Lock` 保护的缓存里，主采样线程读取后写入 `Snapshot`。

实测优化后单次扫描约 1.0 秒，且发生在独立线程，主采样仍保持 1 秒间隔。

进程 CPU 数值按逻辑核心数归一化（`cpu_percent / cpu_count`），与任务管理器“占全部 CPU 的百分比”一致；否则多核进程会显示 300%、1300% 之类的值。

#### 4.3.4 图表绘制

- 采样点保存在 `deque(maxlen=60)` 中，实现固定长度滚动窗口；
- 数据右对齐，最新点在最右侧，横轴步长由“绘图宽度 / 最大点数”决定；
- 纵轴支持固定上限（CPU / 内存 0~100%）与自动取整上限（速率图按 1/1.5/2/2.5/3/4/5/6/8×10ⁿ 取整）；
- 第一条曲线用淡色面积填充，第二条曲线只画折线，保证双曲线互相不遮挡；
- 只有一个采样点时绘制圆点，两个及以上时绘制折线与面积，避免首帧坐标不足报错。

### 4.4 指标与刷新策略

| 指标 | psutil 接口 | 刷新频率 | 展示方式 |
| --- | --- | --- | --- |
| CPU 总体占用 | `cpu_percent(interval=None)` | 每个采样周期 | 大图表 + 统计列 + 左侧列表迷你曲线 |
| 每核心占用 | `cpu_percent(percpu=True)` | 每个采样周期 | “每个 CPU 的利用率”核心网格 |
| CPU 主频 / 核心数 | `cpu_freq()`、`cpu_count()` | 每个采样周期 | 标题副标题 + 统计列 |
| 系统负载 / 运行时长 | `getloadavg()`、`boot_time()` | 每个采样周期 | 统计列 |
| 内存 / 交换分区 | `virtual_memory()`、`swap_memory()` | 每个采样周期 | 大图表 + 内存组成条 |
| 网络收发速率 | `net_io_counters(nowrap=True)` | 每个采样周期 | 大图表（接收/发送）+ 统计列 |
| 网卡状态 / IPv4 / 链路速率 | `net_if_stats()`、`net_if_addrs()` | 每 10 秒 | 网络适配器列表 |
| 磁盘读写速率 | `disk_io_counters(nowrap=True)` | 每个采样周期 | 大图表（读取/写入）+ 统计列 |
| 磁盘分区使用率 | `disk_partitions()`、`disk_usage()` | 每 10 秒 | 分区使用率条 + 百分比 + 容量 |
| 进程列表 | `process_iter()`、`Process.status()` | 每 3 秒 | 进程页表格 + 状态栏进程数 |

使用率颜色规则：< 75% 蓝色，75%~90% 橙色，≥ 90% 红色（用于使用率条与百分比提示）。

## 5. 实现的主要功能

1. **CPU 监控**：总体占用率、每个逻辑核心占用率、主频、物理 / 逻辑核心数、系统负载、运行时长、60 点历史曲线。
2. **内存监控**：物理内存占用率与已用 / 可用 / 总容量、交换分区使用率与容量、内存组成条、历史曲线。
3. **网络监控**：接收 / 发送实时速率（B/s ~ GB/s 自动换算单位）、双曲线、累计流量、网卡连接状态与链路速率。
4. **磁盘 IO 监控**：读取 / 写入实时速率、双曲线、分区数量与总容量。
5. **磁盘分区监控**：盘符、文件系统、使用率条、已用 / 总容量。
6. **进程监控**：名称、中文状态、CPU 占比、内存占用、PID，表头排序与名称筛选。
7. **交互控制**：采样间隔 0.5/1/2/5 秒切换；暂停 / 继续采集；窗口缩放；关闭时安全停止后台线程。
8. **概览状态栏**：进程数、CPU、内存、磁盘速率、网络速率、采集状态、采样次数、运行时长、psutil / Python 版本。

### 6.5 常见问题（FAQ）

| 问题 | 原因与解决 |
| --- | --- |
| `ModuleNotFoundError: No module named 'psutil'` | 未安装依赖，执行 `pip install psutil` 或 `pip install -r requirements.txt` |
| `ModuleNotFoundError: No module named 'tkinter'` | Linux 缺少 Tk，执行 `sudo apt install python3-tk`；Windows 请使用官方 Python 安装包 |
| 启动后进程页短暂显示“正在读取进程列表…” | 进程采样线程首次扫描需遍历全部进程，约 1 秒后出现数据 |
| 进程 CPU 一列最初为 0.0% | `Process.cpu_percent()` 首次调用只建立基线，第二个采样周期后才有数值 |
| 磁盘分区列表为空或缺少某个分区 | 光驱空介质、无权限挂载点、网络盘等会被跳过，属正常现象 |
| 网络 / 磁盘速率为 0 | 当前无网络或磁盘读写活动；可打开浏览器或复制大文件观察曲线变化 |
| 首次启动 CPU 显示 0.0% | `cpu_percent(interval=None)` 首次调用没有参照点，程序已预热；若仍出现，等待下一个采样周期即可 |
| 系统负载显示 0.00 | Windows 上由 psutil 模拟计算，需要程序运行一段时间后才趋于准确 |
| 界面字体偏小或模糊 | 程序已启用 DPI 感知；若系统缩放比例极大，可调整 Windows 缩放设置 |

### 7.3 已知限制

- 网络速率统计的是所有网卡的合计值，未按适配器拆分；
- 磁盘 IO 为物理磁盘合计值，无法按分区区分（受 psutil 接口限制）；
- 进程列表按 CPU 降序只展示前 80 个进程，进程总数单独统计；
- 进程状态为采样瞬间的快照，且只对展示的 80 个进程读取；
- Windows 的系统负载为 psutil 模拟值，精度低于 Linux；
- 历史曲线固定保留最近 60 个采样点，切换间隔后曲线覆盖的时间跨度会变化；
- 进程页只做监控展示，不提供结束进程操作，以免误杀系统进程；
- 程序未打包为 exe，运行需本机安装 Python 与 psutil。

## 附录 B：核心代码片段

速率计算：

```python
def _rate(current, previous, elapsed):
    if current is None or previous is None or elapsed <= 0:
        return 0.0
    delta = current - previous
    if delta <= 0:
        return 0.0
    return delta / elapsed
```

进程采样（名称缓存 + 只对展示条目取状态）：

```python
for proc in psutil.process_iter(["pid", "cpu_percent", "memory_info"]):
    info = proc.info
    pid = info["pid"]
    if pid not in self._names:
        self._names[pid] = self._name_of(proc, pid)
    memory = info.get("memory_info")
    samples.append((
        float(info.get("cpu_percent") or 0.0) / self._cpu_count,
        int(getattr(memory, "rss", 0) or 0),
        pid,
    ))

samples.sort(reverse=True)
for cpu, rss, pid in samples[: self._limit]:
    entry = ProcessEntry(pid, self._names[pid], self._status_of(pid), cpu, rss)
```

采集循环中通过 `time.monotonic()` 计算真实时间差，保证采样间隔抖动时速率依然准确。
