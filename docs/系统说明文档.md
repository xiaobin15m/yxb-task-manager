## 1. 项目概述

本项目实现了一个带图形用户界面的系统监控程序，用于实时观测操作系统的运行状态。程序以 `psutil` 作为底层数据源，以 `tkinter` 构建桌面界面，提供以下监控能力：

1. CPU 总体使用率与每个逻辑核心的使用率；
2. 物理内存、交换分区使用率；
3. 网络接收 / 发送速率；
4. 磁盘 IO 读取 / 写入速率；
5. 各磁盘分区的容量使用率。

界面采用深色主题，并以自绘折线图展示上述指标的历史变化趋势，用户可以切换采样间隔、暂停或恢复采集。

## 3. 开发框架与技术

| 技术 | 作用 |
| --- | --- |
| `psutil` | 跨平台读取 CPU、内存、磁盘、网络、分区等系统指标 |
| `tkinter` / `ttk` 替代方案 | 构建桌面窗口、卡片、按钮、下拉菜单；图表与进度条使用 `Canvas` 自绘，避免引入 matplotlib 等额外依赖 |
| `threading` + `queue` | 后台采样线程与 UI 主线程解耦，避免阻塞界面 |
| `dataclasses` | 以不可变数据类 `Snapshot` / `PartitionUsage` 传递采样结果 |
| `unittest` | 编写格式化函数与采集线程的单元测试 |
| Git + Gitee/GitHub | 源代码版本管理与远程托管 |

### 3.1 为什么选择 tkinter 自绘

- tkinter 属于 Python 标准库，安装成本低，符合“只需 `pip install psutil` 即可运行”的目标；
- matplotlib 嵌入 tkinter 会增加约 40 MB 依赖，并带来字体、DPI 等兼容问题；
- 折线图需求简单（固定窗口、右对齐滚动、自适应纵轴），使用 `Canvas` 自绘约 200 行即可实现，且启动更快。

## 4. 系统设计

### 4.1 总体架构

```
┌────────────────────────────── 主进程 ──────────────────────────────┐
│                                                                    │
│  ┌─────────────────────┐    queue.Queue(maxsize=2)   ┌───────────┐ │
│  │  SystemCollector    │ ──────── Snapshot ─────────▶ │  UI 主线程 │ │
│  │  （守护线程）         │                             │  MonitorApp│ │
│  │  · cpu_percent      │ ◀──── pause / resume / ───── │  · 轮询队列 │ │
│  │  · virtual_memory   │       set_interval          │  · 更新卡片 │ │
│  │  · net_io_counters  │                             │  · 重绘图表 │ │
│  │  · disk_io_counters │                             │  · 状态栏   │ │
│  │  · disk_partitions  │                             └───────────┘ │
│  └─────────────────────┘                                           │
└────────────────────────────────────────────────────────────────────┘
```

- 采集线程每 `interval` 秒采样一次，结果写入容量为 2 的队列；队列满时丢弃旧数据，保证界面拿到的始终是最新快照。
- 界面主线程每 200 ms 轮询一次队列，只做界面更新，不执行任何阻塞式 psutil 调用。
- 磁盘分区容量变化缓慢，默认 10 秒刷新一次；网络与磁盘 IO 每个采样周期都刷新。

### 4.2 模块说明

| `psmon/collector.py` | `Snapshot` / `PartitionUsage` 数据类；`SystemCollector` 采样线程；速率计算；分区读取容错 |
| `psmon/format.py` | 字节容量、速率、图表刻度、运行时长的格式化 |

| `tests/test_psmon.py` | 格式化与采集线程的单元测试 |

### 4.3 关键实现

#### 4.3.1 速率计算

网络与磁盘 IO 使用累计字节计数器，速率按两次采样的差值计算：

```
rate = (counter_now - counter_last) / (t_now - t_last)
```

- 使用 `psutil.net_io_counters(nowrap=True)`、`disk_io_counters(nowrap=True)`，计数器溢出时自动修正，避免出现负值；
- 差值小于 0 时按 0 处理；
- 采集线程启动时先建立基线，暂停期间持续重置基线，恢复后不会出现速率尖峰；
- 首次启动前调用一次 `cpu_percent(interval=None)` 预热，避免第一帧恒为 0。

#### 4.3.2 线程与异常处理

- 采集线程为守护线程，主窗口关闭时 `stop()` 通过事件唤醒并 `join`，避免进程残留；
- 单次采集异常被捕获并记录到日志，不会终止监控线程；
- 读取分区时捕获 `PermissionError` / `OSError`，跳过光驱空介质、无权限挂载点等不可用分区。

#### 4.3.3 界面自适应

- 窗口尺寸根据屏幕分辨率计算，避免在小屏幕上被裁切；
- 三行卡片使用 `grid` 权重分配高度，窗口变矮（< 800 px）时自动提高底部卡片的权重，保证磁盘分区行不被裁切；
- 图表、核心矩阵在 `<Configure>` 事件中按当前画布尺寸重绘，支持任意缩放；
- Windows 下启用 DPI 感知（`SetProcessDpiAwareness`），避免高缩放比例下界面模糊。

#### 4.3.4 图表绘制

- 采样点保存在 `deque(maxlen=90)` 中，实现固定长度滚动窗口；
- 数据右对齐，最新点位于最右侧，横轴步长由“绘图宽度 / 最大点数”决定；
- 纵轴支持固定上限（CPU/内存 0~100%）与自动取整上限（速率图按 1/1.5/2/2.5/3/4/5/6/8×10ⁿ 取整）；
- 单条曲线使用 `stipple="gray25"` 的填充多边形模拟半透明面积图，多条曲线只绘制折线以保持清晰。

### 4.4 指标与刷新策略

| 指标 | psutil 接口 | 刷新频率 | 展示方式 |
| --- | --- | --- | --- |
| CPU 总体占用 | `cpu_percent(interval=None)` | 每个采样周期 | 大号百分比 + 折线图 |
| 每核心占用 | `cpu_percent(percpu=True)` | 每个采样周期 | 核心矩阵（4 列小进度条） |
| CPU 主频 / 核心数 | `cpu_freq()`、`cpu_count()` | 每个采样周期 | 卡片右上角信息 |
| 系统负载 | `getloadavg()` | 每个采样周期 | 1/5/15 分钟文本 |
| 内存 / 交换分区 | `virtual_memory()`、`swap_memory()` | 每个采样周期 | 百分比 + 容量 + 折线图 |
| 网络收发速率 | `net_io_counters(nowrap=True)` | 每个采样周期 | 速率文本 + 双折线 |
| 磁盘读写速率 | `disk_io_counters(nowrap=True)` | 每个采样周期 | 速率文本 + 双折线 |
| 磁盘分区使用率 | `disk_partitions()`、`disk_usage()` | 每 10 秒 | 进度条 + 百分比 + 容量 |

界面配色规则：占用率 < 65% 显示绿色，65%~85% 显示黄色，≥ 85% 显示红色。

## 5. 实现的主要功能

1. **CPU 监控**：总体占用率、16 个逻辑核心分核心占用、主频、物理核心数、系统负载、90 点历史曲线。
2. **内存监控**：物理内存占用率与已用/总容量、交换分区使用率与容量、历史曲线。
3. **网络监控**：下载/上传实时速率（B/s ~ GB/s 自动换算单位）与双曲线。
4. **磁盘 IO 监控**：读取/写入实时速率与双曲线。
5. **磁盘分区监控**：分区设备名、挂载点、文件系统类型、使用率进度条、已用/总容量。
6. **交互控制**：采样间隔 0.5/1/2/5 秒切换；暂停/继续采集；窗口缩放；关闭时安全停止后台线程。
7. **状态栏**：显示采集状态、采样次数、运行时长、当前采样间隔、psutil/Python 版本。

### 6.5 常见问题（FAQ）

| 问题 | 原因与解决 |
| --- | --- |
| `ModuleNotFoundError: No module named 'psutil'` | 未安装依赖，执行 `pip install psutil` 或 `pip install -r requirements.txt` |
| `ModuleNotFoundError: No module named 'tkinter'` | Linux 缺少 Tk，执行 `sudo apt install python3-tk`；Windows 请使用官方 Python 安装包 |
| 磁盘分区列表为空或缺少某个分区 | 光驱空介质、无权限挂载点、网络盘等会被跳过，属正常现象 |
| 网络/磁盘速率为 0 | 当前无网络或磁盘读写活动；可打开浏览器或复制大文件观察曲线变化 |
| 首次启动 CPU 显示 0.0% | `cpu_percent(interval=None)` 首次调用没有参照点，程序已预热；若仍出现，等待下一个采样周期即可 |
| 系统负载显示 0.00 | Windows 上由 psutil 模拟计算，需要程序运行一段时间后才趋于准确 |
| 界面字体偏小或模糊 | 程序已启用 DPI 感知；若系统缩放比例极大，可调整 Windows 缩放设置 |
| 关闭时提示线程仍在运行 | 请通过窗口关闭按钮退出；`stop()` 会唤醒采样线程并等待其结束 |

- 网络速率统计的是所有网卡的合计值，未区分具体网卡；
- 磁盘 IO 为物理磁盘合计值，无法按分区区分（受 psutil 接口限制）；
- Windows 的系统负载为 psutil 模拟值，精度低于 Linux；
- 历史曲线固定保留最近 90 个采样点，切换间隔后曲线覆盖的时间跨度会变化；
- 程序未打包为 exe，运行需本机安装 Python 与 psutil。

## 附录 B：核心代码片段（速率计算）

```python
def _rate(current, previous, elapsed):
    if current is None or previous is None or elapsed <= 0:
        return 0.0
    delta = current - previous
    if delta <= 0:
        return 0.0
    return delta / elapsed
```

采集循环中通过 `time.monotonic()` 计算真实时间差，保证采样间隔抖动时速率依然准确。
